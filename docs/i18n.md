# Internationalisation (français / allemand)

## Principe

- Français = langue par défaut, **sans préfixe** (`/coiffures`). Allemand = préfixe `/de` (`/de/coiffures`).
- Les routes ne sont pas déplacées dans un dossier `[locale]` : `src/middleware.ts` réécrit `/de/...` vers la même route interne et pose la langue (en-tête de requête `x-locale` + cookie `NEXT_LOCALE`, mémoire de la dernière langue, sans effet sur l'URL).
- `/fr/...` est redirigé (308) vers l'URL sans préfixe ; `/de/dashboard`, `/de/connexion`, `/de/api` redirigent vers la route réelle. Le **dashboard reste en français**.
- Aucune redirection automatique selon la langue du navigateur : seul un encart discret et fermable (`LanguageSuggestion`) propose l'autre langue.

## Code

| Besoin                         | API                                                                                                                                                                        |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Langue d'une requête (serveur) | `getLocale()`, `getI18n()` (`src/i18n/server.ts`) : `{ locale, messages, t, msg, path }`                                                                                   |
| Langue côté client             | `useI18n()` / `useT()` (`src/i18n/client.tsx`) ; `LocaleProvider` dans le layout (espaces `common` + `nav`), `I18nScope` pour ajouter un espace de noms (ex. `booking`)    |
| Liens, routeur, chemin courant | `Link`, `useRouter`, `usePathname` de `@/i18n/link` (préfixe `/de` automatique)                                                                                            |
| URL                            | `localePath(locale, '/faq')`, `absoluteUrl(locale, path)` (e-mails), `localeRedirect(path)`                                                                                |
| Dictionnaires                  | `src/i18n/messages/{fr,de}/<espace>.ts` ; l'allemand est typé sur le français (clés identiques, vérifiées par `tsc`)                                                       |
| Pluriels / formats             | `t('clé', { count })` avec `{ one, other }` (Intl.PluralRules) ; `formatEuro`, `formatDate`, `formatDuration` (`src/i18n/format.ts`)                                       |
| Métadonnées                    | `pageMetadata({ locale, path, title, description })` : title, description, OG, Twitter, canonical, hreflang fr/de/x-default                                                |
| Erreurs serveur / Zod          | Restent en français à la source ; traduites à l'affichage par `msg()` grâce au catalogue `src/i18n/messages/de/server/*.ts` (clé = texte français exact, paramètres `{0}`) |

## E-mails

La langue est mémorisée dans la colonne `locale` (défaut `'fr'`) de `Appointment`, `CustomRequest`, `Conversation`, `Review`, `WaitlistEntry` (migration additive `add_locale_to_customer_facing_entities`). Chaque notification client porte `payload.locale` ; `templates.ts` rend sujet, texte et HTML dans cette langue (français si absent). Les e-mails destinés à l'administratrice restent en français. La langue de l'évaluation capillaire est stockée dans `answers.__locale` (retirée à l'affichage).

## Contenus saisis par l'administratrice

Prestations, descriptions, options, règles, textes de politique, signature d'e-mail : **affichés dans la langue saisie, sans traduction automatique**. Seules les 7 catégories par défaut (par slug) et les libellés fixes du code sont traduits.

## Ajouter une langue ou un texte

1. Ajouter la clé dans `fr/<espace>.ts` puis `de/<espace>.ts` (le compilateur signale un oubli).
2. Message d'erreur serveur affiché au public : ajouter la paire français -> allemand dans `de/server/<domaine>.ts`.
3. Nouvelle page publique : `generateMetadata` avec `pageMetadata`, `Link` de `@/i18n/link`, `<I18nScope>` pour les composants clients.
